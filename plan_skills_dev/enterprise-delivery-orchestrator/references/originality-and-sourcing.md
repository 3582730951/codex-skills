# Originality And Sourcing

Use this file to prevent copying and generic AI-shaped work.

## Inspiration Log

If external inspiration is used, record:

- source
- what principle was taken
- what was deliberately changed
- license or usage status for any asset

## Never Copy

Do not copy:

- third-party page structure wholesale
- product copy or slogans
- icons, photos, illustrations, or fonts with unclear rights
- code skeletons or API names from unrelated products
- component structures just because they are common in generated output

## Naming Rules

Prefer names derived from:

- product domain terms
- repository vocabulary
- exact responsibility

Reject:

- `processData`
- `handleThing`
- `ServiceManager`
- `CardGridSection`
- similarly vague or template-like names in core code

## Comment Rules

Comments should explain:

- why a decision exists
- why a boundary is strict
- why a cleanup or ordering rule matters

Comments should not narrate obvious statements such as "set variable" or "call function".

## Low AI-Smell Checks

Flag the work if it shows:

- too many identical patterns across unrelated modules
- architecture that feels copied from tutorials rather than the repository
- ornamental abstractions with no domain reason
- generic UI sections or boilerplate service layering

The point is not novelty for its own sake. The point is task-specific work that looks owned, not pasted.
